# M19 — The `pdfrum` command line

**Design:** `docs/design/pdfrum-cli.md` (§9 is the scoped version).
**Started:** 2026-09-05.

## Phase 1 — foundation and the read-only core

`crates/pdfrum-cli`, binary `pdfrum`, on `clap` + `serde_json` and the
facade crate only. Commands: `info`, `doctor`, `render`, `extract
text|links|toc|attachments|annotations|signatures`; `--json` on every
inspection command, `--pages` with the `1-3,5,7-end` grammar, `--password`,
`-` for a single PNG to stdout, notices on stderr, a closed pipe treated
as the reader being done. Exit codes 0 / 1 / 2 (clap) / 3 (`doctor
--strict`).

**Facade fills** (each on `pdfrum`'s API baseline): `Document::id()` (the
trailer `/ID` pair), `Page::{bleed_box, trim_box, art_box}`,
`Page::page_links()` with `PageLink { rect, target: LinkTarget::{Page, Uri,
Other} }` — the raw `Page::links()` needed the catalog, the limits and a
page-index closure to resolve, which no facade client should have to hold.

**Tests:** `crates/pdfrum-cli/tests/cli.rs` runs the binary on nine
fixtures (`tests/fixtures/PROVENANCE.md`) and compares stdout with
`tests/expected/*.txt`; every `--json` output parses and is checked for its
keys; piping into a closed reader exits 0.

**Deviations from the design:** none in scope; `--color`, `--hyperlinks`
and the terminal crates arrive with phase 3, so no flag without a reader
exists yet.

## Phase 2 — surgery, forms, whole-file commands

`pages merge|split|slice|reorder|create|nup|booklet`, `forms
dump|fill|flatten`, `repair`, `optimize`, `security decrypt`, and
`--deterministic` on every writing command (the `/ID` seeded from the
input's bytes, so the same input gives the same output bytes anywhere).

**Library work the design under-scoped.** §9.1 called `pages create` and
`slice` composition; neither was. The edit crate had page import and N-up
and nothing else that touches the page tree, so `pdfrum-edit` gained
`pages.rs`: `add_blank_page`, `delete_pages` (unlinking from any depth of
tree, every `/Count` above decremented), `set_page_rotation`,
`set_page_box`, with five tests over flat and nested trees. The facade
gained `Document::blank(width, height)` (a correct four-object file written
in memory), `DocEdit::{import_pages, delete_pages, add_page, set_rotation,
set_page_box, n_up}`, `SaveOptions::id_source` with `IdSource` and
`PageBox` re-exported.

**How the commands compose.** `merge` imports every other file into the
first; `split` and `slice` delete from the source, so a page keeps its
identity and can be rotated or cropped by its own index; `reorder`, `nup`
and `booklet` import into a blank document and then delete the blank's
own page, which is why they cannot also rotate — that is `slice`'s job
and the help says so. `booklet` pads to a multiple of four with blank
pages through a first in-memory save, then lays the folding order out
two-up. `create` first builds a document with one blank page per image,
saves it in memory, and only then draws on the pages, because a page has
to exist before it can be edited. `repair` and `optimize` are the same
full rewrite; their help says so.

**Dependencies:** `png` (already a tool row) for decoding PNG input to
`pages create`; JPEG input is embedded as it is, with the frame size read
from the SOF marker.

**Tests:** nine more in `tests/cli.rs`, three new fixtures with provenance
(`text_form.pdf`, `encrypted.pdf` with its password, `mona_lisa.jpg`), a
PNG generated in the test. Byte-identical `--deterministic` output is
asserted, not assumed.

**Not done, and named:** `forms fill` does not run the document's
calculation scripts — that needs the `javascript` feature and a
`FormSession`, phase 5's territory alongside `security encrypt`.

## Phase 3 — the terminal

`preview` (one page, right there), `view` (a pager: `j`/`k`, `g`/`G`,
`+`/`-` zoom, `/` search with `n`, `q`; raw mode and the alternate screen
restored whatever happens), `search` (`grep` for a document: every hit
with its line, page and boxes; exit 1 when nothing matched), and three
global flags — `--color`, `--hyperlinks`, `--graphics` — each
`auto|always|never` (or a protocol), decided once in `term.rs` from the
flags and the environment (`NO_COLOR`, `TERM=dumb`, `TERM_PROGRAM`,
`KITTY_WINDOW_ID`, `COLORTERM`) and off whenever stdout is not a terminal.
`extract links` and `extract toc` wrap targets in OSC 8 (`file://…#page=N`
for pages); `search` paints hits. An encrypted file opened at a terminal
without `--password` asks for one, silently.

**Pictures without `viuer`:** its half-block path pulls an LGPL crate, so
kitty's APC chunks, iTerm2's OSC 1337 and truecolor half-blocks are written
directly, ~120 lines with a base64 encoder pinned to the RFC vectors. No
sixel: the only Rust implementation on offer wraps libsixel.

**Dropped, and why:** `comfy-table` and `indicatif` were admitted and then
removed in the same phase: tables and progress only render at a terminal,
which the tests never are, so they were options without a reader the tests
could see. `DEPS.md` records all three.

**Tests:** search text, JSON and exit code; a half-block preview forced
through `--graphics halfblock` into a pipe; `--hyperlinks always` and
`--color always` in a pipe, and `NO_COLOR` winning over `auto`; `view`
refusing a pipe with a pointer to `render`.

## Phase 4 — `pdfrum-markdown`

A library crate beside `pdfrum-text` and `pdfrum-doc`, not on the facade:
its inputs are the page graph, the resolver and the structure tree, and the
facade's `Page::markdown()` / `Page::layout_text()` (feature `markdown`)
are one call each into it. The command line gains `extract markdown` and
`extract text --layout`.

**Two tiers, one line model.** `lines.rs` walks the extractor's characters
into lines with a box, a median font size, bold/mono votes from the fonts'
names (the graph walked in the extractor's own numbering, so the join is
exact) and the marked-content id per character run; a character drawn
twice in one place (faux bold) is kept once. `tagged.rs` reads the tree —
headings by level or nesting depth, paragraphs, lists with labels, tables
through `THead`/`TBody`, figures with `/Alt` or `/ActualText`, a figure
nested in a paragraph still a figure — joining each element to the text
under the ids it names. **What the tree does not claim is not lost:** an id
the tree marks invalid (PDFium's rule for a kid whose element names no
page, which this crate follows) leaves its text to the typographic tier,
appended after the tree's blocks. `heuristics.rs` is that tier: body size
by weighted mode, 1.6×/1.3× headings, short bold `###`, monospaced code,
bullets and numbers, paragraph reflow with de-hyphenation, ligatures, an
8% margin band that only applies once a page has enough lines to have a
header. `layout.rs` prints the same lines where they sit, one cell per
half-em, rows by baseline, blank lines by the space between them.

**A convention learned:** the text page's boxes are y-down. The first
draft assumed page space; the reading order of the fixture's links said
otherwise, and every comparison flipped.

**MinerU:** the rules are the ones its non-learned pipeline uses,
implemented from their description; no code was copied (DEPS.md, and the
crate's README credit the method).

**Tests:** unit tests over synthetic lines for every rule, the renderer's
block kinds, and the RFC base64 vectors are elsewhere; three tagged
fixtures with provenance pin the tree tier, the unclaimed-text rule, and
`--layout` keeping the same words with columns placed.
