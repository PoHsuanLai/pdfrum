# M17 — the small APIs, closed

PLAN.md's M17 names five of the reference implementation's minor API families
and one exit criterion: every listed embedder-test assertion ported and
passing. All five landed on 2026-09-04, through the oai bridge (generation)
with local application, gates, the board and the landing.

| family | oracle tests | ported as | what was new |
|---|---:|---|---|
| searchex | 6 | `tests/searchex.rs` (4) | nothing — both index maps existed; the tables are pinned |
| attachments | 14 | `tests/attachments.rs` (13) | readers `Attachment::{description, subtype, param, has_param}`; writers `DocEdit::{add_attachment, set_attachment_file, set_attachment_param, set_attachment_description, delete_attachment}` |
| signatures | 10 | `tests/signatures.rs` (8) | `Document::signatures`, `Signature::{contents, byte_range, sub_filter, reason, time, doc_mdp_permission}` |
| thumbnails | 14 | `tests/thumbnails.rs` (7) | `Page::{thumbnail, thumbnail_raw, thumbnail_data}`, `pdfrum_render::image_to_pixmap` |
| flatten | 13 | `tests/flatten.rs` (9) | `DocEdit::flatten(page, FlattenMode) -> Flattened` |

Fewer tests than the oracle because a typed API collapses its
null-handle and buffer-length cases: every value the oracle asserts is
asserted.

## Rulings

- **Thumbnails are pinned to within one count of the oracle's decoder.** The
  fixtures' thumbnails are DCT-encoded and two JPEG decoders round a few
  samples one count apart (18 and 9 of 10 000 bytes); the unfiltered
  thumbnail matches exactly.
- **An empty embedded file decodes to nothing.** The filter chain's
  empty-output fallback handed back the raw compressed bytes for a Flate
  stream of an empty file; it now applies only when a decoder complained,
  which is the corrupt-stream case it was written for.
- **Flatten, two corrections over the reference, both cited in the tests:**
  an appearance stream with no box of its own is drawn over the annotation's
  extent rather than skipped (crbug.com/861842, whose page the reference
  renders blank and whose own test says it should not); and a widget with no
  appearance, or a form asking for regeneration, is flattened from the
  appearance a viewer generates — the reference does the same, at load time.
  The flattened saves are pinned to the oracle's own expectation pictures to
  within the two engines' text anti-aliasing (under 0.5% of bytes).
- **The attachment name tree is rewritten flat on every change.** One
  `/Names` array sorted by name, `/Kids` and `/Limits` dropped: equivalent for
  every reader and free of the leaf search the reference ports.
- **`CreationDate` is not written automatically.** The reference stamps the
  wall clock into a new embedded file's `/Params`; a save that depends on the
  clock is not reproducible, and the key is optional. A caller who wants one
  sets it with `set_attachment_param`.

## Two performance regressions the ratchet surfaced on the way

Running the full benchmark suite for the re-baseline (§8 of the M13
document) found 75 regressions against the 2026-09-02 baseline. Two were
real and are fixed: the 16-bit rounding fix had put a libm `round` on every
sample of every image (`+50%` on a 5100x6600 decode; now add-a-half and
truncate, proved identical by the existing exhaustive tests), and the
annotation overlay built the form's default faces on every page, including
pages with no annotations (4–6 ms per cold render since M14; now built only
for a page with a widget, a free-text annotation or a pop-up to draw).
