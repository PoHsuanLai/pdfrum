## Phase 2 — facade: `Page::words`

`Page::words(&self) -> Vec<Word>` on `pdfrum`, with `Word { text, rect,
range, font, size }` — the shape `extract words --json` and a citation
pipeline want. It is a view over the text page the extractor already
builds, not a second layout: `Page::text()` is extracted once and
`TextPage::words` splits `chars` on whitespace in reading order (a
generated space or line break, or any Unicode whitespace). A word's
`text` is `TextPage::slice` over its `range`, so it slices back out of the
text page for context; its `rect` is the union of its glyphs' `char_box`es,
in the same page space `TextPage::rects` and `PageLink::rect` use (the
page's own y-up, unrotated coordinates — on `hello_world_2_pages.pdf` the
line set at `20 50 Td` reports `x0 ≈ 20` and a box straddling `y = 50`);
`font` and `size` come from the first character. `size` is the `Tf`
operand scaled by the text matrix's vertical scale, so a `1 Tf` under a
`12 0 0 12` matrix reads as 12 points rather than 1. The scripting API's
word list (`pdfrum_text::words`, `Doc.getPageNthWord`) is a different
reading of "word" and is untouched.

**What `pdfrum-text` had, and what it gained.** `CharBox` already carried
`char_box`, `font_size`, `matrix` and the `ObjectIndex` of the text object
that drew it, but no font name reached the text page. `TextPage` gained a
`fonts: BTreeMap<ObjectIndex, String>` filled in `extract` from each run's
`Font::base_font_name` (the subset tag stripped and standard-14 aliases
canonicalized, as the font crate already normalizes it — `Times-Roman`, not
`ABCDEF+Times-Roman`; a Type 3 font has no base name and is absent), read
through a character by `TextPage::font_name(CharIndex)`, and
`TextPage::words` with the `Word` type, which the facade re-exports. Unit
tests in `crates/pdfrum-text/src/word.rs` pin the split, the ranges, the
box union, the matrix-scaled size and the font lookup on a synthetic page;
`crates/pdfrum/tests/words.rs` pins the fixture's four words per page, the
left-to-right non-overlapping boxes, the fonts (`Times-Roman`,
`Helvetica`) and sizes (12, 16 — read off the content stream), and the
corpus guide's first page (45 words, every one non-empty with a
positive-area box).

**Untouched:** nothing a renderer or extractor already calls changed; the
`fonts` field is additive and every existing `TextPage` reader is
indifferent to it. The conformance board is byte-identical by construction.
