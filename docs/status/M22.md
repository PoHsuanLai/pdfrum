## Phase 1 — owned handles

### What

Three additions to `crates/pdfrum`, each on its own commit, each beside the
API that was already there rather than in place of it:

- **`OwnedPage`.** `Document::page_owned(self: &Arc<Self>, index) ->
  Result<OwnedPage>` and `Document::pages_owned(self: &Arc<Self>) -> impl
  Iterator<Item = Result<OwnedPage>>`. The handle carries the read-only
  surface of `Page` under the same names — `width`, `height`, `media_box`,
  `crop_box`, `bleed_box`, `trim_box`, `art_box`, `rotation`, `render`,
  `render_on`, `text`, `text_on`, `words`, `annotations`, `links`,
  `page_links`, `images`, `structure`, `layout_text`, and `markdown` /
  `markdown_blocks` with the `markdown` feature — plus `document()` and
  `index()`. `Send + Sync`.
- **`OwnedFormSession`.** `FormSession::owned(Arc<Document>)`,
  `owned_with_config(Arc<Document>, SessionConfig)` and, with the
  `javascript` feature, `owned_with_scripts(..)`. The event and value
  surface of `FormSession` under the same names: the mouse and key events,
  `apply`, `focus_at`, `blur`, the focus/hover/popup/scroll queries, the
  choice-row queries, undo and redo, the text getters and
  `replace_selection`, `load_page`, `open_document`, `page_opened`,
  `page_closed`, `advance_time`, `honour_focus_requests`, and the script
  accessors under the feature.
- **`ErrorCode`.** `Error::code(&self) -> ErrorCode`, where `ErrorCode` is
  `#[repr(u32)]` and `#[non_exhaustive]` with one documented number per
  `Error` variant — `Io` 1, `Open` 2, `WrongPassword` 3, `Read` 4,
  `Render` 5, `Doc` 6, `Save` 7, `Text` 8, `Limit` 9. `Save`'s number is
  reserved even with the `edit` feature off, so the numbering does not
  shift with the feature set. `From<ErrorCode> for u32` yields the number;
  `Display` on `Error` is unchanged, so the message is what it always was
  and the code travels beside it.

### Why

A C caller cannot carry a lifetime. `Document::page(&self) -> Page<'_>` and
`FormSession::new(&doc)` are the right Rust shapes and they stay, but there
is no way to express `Page<'_>`'s borrow in a `void *` a host program holds
across calls, stores in its own struct, or hands to another thread. The
owned handles keep an `Arc<Document>` instead, so a handle is a plain value
with no obligations on the caller beyond freeing it: phase 2 can hand one
out as an opaque pointer and the document stays alive exactly as long as
any page or session of it does. Rust callers get the same relief wherever a
page has to outlive the scope that opened the document — a page stored in a
struct beside its document, or sent to a worker thread.

`ErrorCode` exists for the same boundary. A C header needs a number and a
JSON error body needs a stable field; matching on the Rust enum is not
available to either, and a `Display` string is not something a caller can
branch on. `#[non_exhaustive]` plus fixed numbers means a new variant is an
added row, never a renumbering.

### One implementation underneath

No method is a second copy of the borrowed one. `OwnedPage` is `{ doc:
Arc<Document>, page: PageRecord }` — not a self-referential struct — and
each method lends its record to a `Page<'_>` built for the length of the
call, then calls the borrowed method. `Page::dict` became an `Arc<PageDict>`
so that lend is one reference-count bump rather than a dictionary copy, and
the boxes and rotation a `Page` reads at load are read once when the handle
is built and kept, so nothing is re-derived per call.

`OwnedFormSession` does the same trick with the session's state:
`FormSession`'s fields became one `State` record, and the owned session
moves that record into a `FormSession` over a borrow of the held document
for the length of a call and takes it back afterwards, leaving a vacant
`State` in the slot meanwhile. The getters that read only state live on
`State` and both sessions call them.

### The measurement

One page of `benches/fixtures/foxittext.pdf` (595×841) rendered on the
`vello-cpu` backend, release build, whole process counted by `valgrind
--tool=callgrind`, each path run twice:

| path     | run 1       | run 2       |
| -------- | ----------- | ----------- |
| borrowed | 107,655,293 | 107,655,302 |
| owned    | 107,655,027 | 107,658,806 |

Run noise on the borrowed path is 9 Ir. The owned path lands 266 Ir below
the borrowed one on the first run and 3,504 Ir above it on the second — a
spread of ±0.004% around the borrowed figure, in both directions, on a
107 M Ir render. The owned path is not measurably slower: what it adds per
call is the `Arc` clone and the `Page` reconstruction, and both are lost in
the noise of the render itself.

### What phase 2 builds on

`crates/pdfrum-capi` (PLAN.md §M22.2) needs exactly three things from the
Rust side, and phase 1 is all three:

- an opaque page handle it can `Box::into_raw` and hand to C without a
  lifetime parameter — `OwnedPage`, reached through `pdfrum_page`;
- the same for forms — `OwnedFormSession`, behind `pdfrum_form_*`;
- a number for every failure, so `pdfrum_open`'s error out-parameter and
  every other fallible call can report a kind as well as a message —
  `ErrorCode`, whose numbers become the `PDFRUM_ERR_*` constants
  `cbindgen` emits into `pdfrum.h`. The table test in `error.rs` pins each
  one, so a changed number is a changed header and a deliberate commit.

Cancellation, the third item in PLAN.md §M22.1, is the host-set flag M20
phase 3 already added; the capi crate wires `pdfrum_cancel` to it and
nothing new was needed here.

## Phase 2 — `libpdfrum`

**PLAN.md §M22 items 2 and 3.** Phase 1 was a facade fill; phase 2 is the
library that stands on it. Nothing under `crates/pdfrum/src` moved: the facade
had everything phase 1 said it would — `OwnedPage` through `Document::page_owned`,
`OwnedFormSession` beside `Form`, `ErrorCode` for the numbers, and the
`Deadline` M20 phase 3 added for cancellation.

### What

`crates/pdfrum-capi`, a new workspace member with **one dependency**, `pdfrum`.
It builds `libpdfrum.so` and `libpdfrum.a` from `crate-type = ["cdylib",
"staticlib"]`, and cbindgen generates `include/pdfrum.h` from the Rust
signatures.

**The two names, and why they differ.** The shipped artefact is `libpdfrum`,
because that is the product and `-lpdfrum` is what a C build writes; the name
comes from `[package.metadata.capi.library]` and is what `cargo cinstall` lays
down. The *Rust lib target* is `pdfrum_capi`, and it has to be: this crate
depends on the facade, whose lib target is `pdfrum`, and two lib targets of one
name in a workspace collide twice over. `cargo test --doc` gets two `--extern
pdfrum` candidates and fails with E0464, and `cargo doc --workspace` would write
both crates' pages to `doc/pdfrum/`, which cargo refuses rather than clobbering.

Both collisions were found by running the full `scripts/ci.nu`, not by reading
the manifest, and the second is worth recording because the obvious fix is the
wrong one. Cargo suggests `doc = false`, which does silence it — and makes this
crate's `RUSTDOCFLAGS='-D warnings' cargo doc` gate **vacuous**. That was
checked rather than assumed: with `doc = false`, a deliberately planted broken
intra-doc link passed silently. Renaming the lib target keeps the gate real, and
it immediately earned its keep by catching an actual unresolved link that had
been sitting in `pdfrum_document_page`'s doc comment since the first commit.

The cost is that a plain `cargo build` writes `libpdfrum_capi.so` rather than
`libpdfrum.so`. `ctest/run.sh` and `scripts/capi-header.nu` accept either name,
preferring the shipped one, and `cargo cinstall` — the path that matters to a
consumer — installs `libpdfrum.*` regardless.

**Fifty-four declared functions over ten opaque handles.** The handles are
`pdfrum_document`, `pdfrum_page`, `pdfrum_form`, `pdfrum_cancel`, and six list
handles — `pdfrum_words`, `pdfrum_links`, `pdfrum_bookmarks`,
`pdfrum_attachments`, `pdfrum_hits`, `pdfrum_images`. Grouped:

| Area | Functions |
|---|---|
| Open and close | `pdfrum_open`, `pdfrum_open_with`, `pdfrum_open_file`, `pdfrum_close` |
| Pages | `pdfrum_page_count`, `pdfrum_document_page`, `pdfrum_page_close`, `pdfrum_page_size` |
| Render | `pdfrum_page_render_size`, `pdfrum_page_render` |
| Text | `pdfrum_page_text`, `pdfrum_page_words`, `pdfrum_page_search`, `pdfrum_page_markdown` (feature) |
| Lists (×6) | `*_count`, `*_get`, `*_free` for each of the six, plus `pdfrum_attachments_data` and `pdfrum_images_pixels` |
| Document queries | `pdfrum_page_links`, `pdfrum_document_bookmarks`, `pdfrum_document_attachments`, `pdfrum_document_images`, `pdfrum_document_metadata`, `pdfrum_metadata_free` |
| Forms | `pdfrum_form_open`, `pdfrum_form_field_count`, `pdfrum_form_field`, `pdfrum_form_set`, `pdfrum_form_set_checked`, `pdfrum_form_save`, `pdfrum_form_free` |
| Save | `pdfrum_document_save` |
| Cancellation | `pdfrum_cancel_new`, `pdfrum_cancel_stop`, `pdfrum_cancel_free` |
| Housekeeping | `pdfrum_version`, `pdfrum_free`, `pdfrum_error_free` |

Two `#[repr(u32)]` enums reach the header as named constants —
`PDFRUM_CODE_*` (the facade's `ErrorCode` one for one, plus `OK` 0 and
`ARGUMENT` 100 for the boundary's own failures) and `PDFRUM_FIELD_KIND_*` —
and five `#[repr(C)]` value structs: `pdfrum_error`, `pdfrum_buffer`,
`pdfrum_limits`, `pdfrum_save_options`, `pdfrum_metadata`, plus the six item
structs the list getters fill.

The rules are in **docs/design/capi.md**: the unsafe rule, the type rule, the
memory rule, the thread rule, the error rule, and the naming.

### Two decisions worth recording

**One `pdfrum_free` for every string and buffer.** Rust's allocator needs the
exact layout a block was made with, and a `pdfrum_buffer` of arbitrary bytes
cannot recover its length by scanning for a NUL the way a `char *` can. So the
crate's single allocator writes a length word *ahead* of the payload and hands
out a pointer to the payload. One word per allocation buys a header with one
free function instead of `pdfrum_free_string` and `pdfrum_free_buffer` and the
first caller who confuses them.

**Lists are handles, not caller-filled arrays.** Every item carries at least
one string. An array would have meant either a per-item free — six more
functions, and a leak for every caller who forgets one — or a sizing call
before every read. A handle owns its items *and* their strings, so
`pdfrum_words_free` is the only free a caller needs and there is no per-word
one at all. The strings are borrows into the handle and the header says so on
every getter.

### The C test, and what it found

`crates/pdfrum-capi/ctest/test.c`, compiled with `-std=c11 -Wall -Werror`
against the generated header and linked against the built library. **44 checks,
all passing.** It opens `hello_world_2_pages.pdf` from bytes and frees the
caller's buffer immediately — testing the "bytes are copied" promise, since
everything after reads the document — counts two pages, renders and finds a
non-white pixel, extracts the text and finds `Hello, world!`, lists four words,
searches, fills `text_form.pdf` and saves it to bytes and **reopens those
bytes** to read the value back through a fresh form, and gets code 3 with a
message from `encrypted.pdf` with a wrong password. It walks the null contract
throughout: a null handle is refused with `PDFRUM_CODE_ARGUMENT`, an index past
the end is answered rather than crashed on, and every free tolerates null.

**The eight-thread result.** Eight pthreads each take their own `pdfrum_page`
of one shared `pdfrum_document` and render at scale 2. Both halves are
asserted, because a racing renderer would pass only the first: every render
succeeded, and **every pixmap was byte-identical to a single-threaded render** —
8 threads × 400×400 RGBA, all identical.

It earned itself on its first run. `pdfrum_page` had been both the opaque type
and the function returning one; C has a single namespace for both, so the
function declaration shadowed the typedef and no caller could declare a
`pdfrum_page *` after it. Every Rust gate was green, because Rust has two
namespaces. The accessor is now `pdfrum_document_page`. That defect is the
argument for the C test in one sentence: no Rust test can see it.

### The header under the snapshot

`scripts/capi-header.nu` gives the header the discipline WP13 gave the Rust
baselines, with two checks that fail for different reasons:

- **Drift** — regenerate into a temp file and compare against the committed
  header. A difference means a signature or doc comment moved without a
  regeneration.
- **Symbols** — `nm -D` the release cdylib and diff its exported `pdfrum_*`
  functions against the header's declarations, both directions. A symbol with
  no declaration is unreachable from C; a declaration with no symbol is a link
  error waiting for the first caller. The drift check cannot see either,
  because both sides of *its* comparison come from one source file.

Measured: 54 declared, 53 exported, the difference being `pdfrum_page_markdown`
under its `#ifdef PDFRUM_MARKDOWN` guard — named in a `FEATURE_GUARDED`
constant and exempt in one direction only. Both halves were proved to fail on a
planted fault before being trusted: an appended `/* planted */` line is
reported as drift, and a planted name in the declared set is reported as
declared-but-not-exported.

### Packaging

`cargo cinstall --release --prefix <dir>` installs six files:

```
<prefix>/include/pdfrum.h
<prefix>/lib/x86_64-linux-gnu/libpdfrum.a
<prefix>/lib/x86_64-linux-gnu/libpdfrum.so -> libpdfrum.so.0.1.0
<prefix>/lib/x86_64-linux-gnu/libpdfrum.so.0.1 -> libpdfrum.so.0.1.0
<prefix>/lib/x86_64-linux-gnu/libpdfrum.so.0.1.0
<prefix>/lib/x86_64-linux-gnu/pkgconfig/pdfrum.pc
```

Verified by compiling and running a C program against the *installed* package:
`pkg-config --cflags --libs pdfrum` resolves, the program links, and it prints

from the committed one only by the `PDFRUM_MAJOR`/`MINOR`/`PATCH` macros
cargo-c adds, which is why the drift check regenerates with `cbindgen` directly.

### Dependencies

**None added.** `pdfrum-capi`'s only dependency is `pdfrum`, and the pure-Rust
check walks this crate with every other and still passes. `cbindgen`, `cargo-c`
and a C compiler are recorded in DEPS.md as **tools**, in their own section
that spells out why a C compiler in a test stage is not a hole in the pure-Rust
guarantee: that guarantee is about what the library compiles and links, and the
C program is a consumer of the shipped library rather than part of it.

## Phase 4 — `pdfrum-wasm`

**PLAN.md §M22 item 4.** The other binding on the phase-1 handles: what phase 2
gave C, this gives JavaScript. Nothing under `crates/pdfrum/src` moved — the
facade had everything this needed, as it had for the C crate: `OwnedPage`
through `Document::page_owned`, `Form` for the buffered fill, `ErrorCode` for
the numbers, `Deadline::manual` for cancellation.

### What

`crates/pdfrum-wasm`, a new workspace member with **three dependencies**:
`pdfrum`, `wasm-bindgen` and `js-sys`. `crate-type = ["cdylib", "rlib"]` — the
`cdylib` is the module, the `rlib` is so clippy, rustdoc and `--all-targets` on
the host have a Rust library to look at.

**Four handles, twelve value types, one function.** The exports, as the
generated `pdfrum.d.ts` declares them:

| `Form` | `open`, `fields`, `set`, `setChecked`, `save`, `free` |

The rules — the shape, the memory rule (`free()`), the error contract
(`.code`), the features and the budget — are in **docs/design/wasm.md**.

### Three decisions worth recording

**Typed structs, not `serde-wasm-bindgen`.** A plain object reaches TypeScript
as `any`, and the TypeScript types are part of what PLAN.md §M22.4 asks for. So
every structured return is a `#[wasm_bindgen(getter_with_clone)]` struct:
sixteen named classes with typed fields in the `.d.ts`, at a cost of one `pub`
field per value. The option objects are classes for the same reason plus a
second — a plain object arrives in Rust as a `JsValue` this crate would have to
reflect field names out of one string at a time.

**`Clamped<Vec<u8>>` for pixels.** `RenderResult.data` and `ImageInfo.data`
type as `Uint8ClampedArray`, which is what `new ImageData(data, width, height)`
requires. Returning a plain `Uint8Array` would have made every caller copy the
buffer a second time to display it. The straight-alpha conversion happens in
the binding too, rather than being left to a caller who would have to know it
was needed.

**One error conversion.** A single `From<Failure> for JsValue` builds a real
JavaScript `Error` — so a caller gets `.stack` and `instanceof Error` — and
sets `code` on it. No per-function string anywhere. The numbers are the
facade's `ErrorCode` one for one, the same table `pdfrum.h` names
`PDFRUM_CODE_*`, plus 100 for an argument this layer rejected.

### What the target takes away

**No threads**, so the C library's one-document-many-workers shape has no
equivalent and needs none.

**No clock.** `Instant::now()` panics on `wasm32-unknown-unknown`, so
`Deadline::after` cannot be constructed and there is no `timeLimitMs` option.
The one stopping mechanism is `Cancel`, the host-set flag on
`Deadline::manual`, raised from the host's own `setTimeout` or abort handler.
Not a lesser substitute: the facade checks the flag at exactly the points it
would have checked a clock, so the only difference is who owns the timer — and
on the web the host owns it already.

### The tests

**13 under Node, all passing**, through `wasm-bindgen-test-runner`. Fixtures
are embedded with `include_bytes!`, there being no filesystem on this target —
which is also the shape a real caller has, handing the module a `Uint8Array`.

```
test version_is_the_crate_version ... ok
test search_and_markdown_and_metadata_answer ... ok
test renders_a_page_with_ink_on_it ... ok
test opens_and_counts_pages ... ok
test fills_a_form_saves_it_and_reads_the_value_back ... ok
test extracts_text_and_words ... ok
test an_index_past_the_end_throws ... ok
test a_wrong_password_throws_code_three ... ok
test a_raised_cancel_flag_stops_a_render ... ok
test a_pixel_limit_throws_code_nine ... ok
test a_page_outlives_its_document ... ok
test a_document_with_no_form_is_refused_at_the_open ... ok
test a_bad_scale_is_rejected_as_an_argument ... ok

test result: ok. 13 passed; 0 failed; 0 ignored; 0 filtered out
```

Each is there for a failure it can see. The render asserts **a non-white
pixel**, because a render that drew nothing would pass a size check alone. The
form test **reopens the saved bytes** to read the value back, because a save
that wrote into a place nothing reads would pass every assertion above it. And
one test frees a document and then uses a page of it, which is the memory rule
a caller is most likely to get wrong.

The test corrected a doc comment on its first run: `Document.page` claimed
`.code === 6` for an index past the end, and the facade actually reports 4
(`Read`, "no page at index 99"). Asserting the number rather than "some code"
is what caught it, and a caller branching on it needs the number to be the same
one every time.

**Running from inside the crate is load-bearing.** The runner is named in
`crates/pdfrum-wasm/.cargo/config.toml`, and cargo reads a `.cargo/config.toml`
relative to the invocation directory rather than the manifest. From the root
with `--manifest-path` the tests build and then fail with `Exec format error`,
cargo having tried to execute the `.wasm` itself. `scripts/ci.nu` `cd`s in.

### The sizes, and the budget

Measured on the shipped `_bg.wasm`, all three profiles built and bindgen'd and
optimized:

| `opt-level` | raw | after `wasm-bindgen` | after `wasm-opt -Oz` |
|---|---|---|---|
| `3` | 5,650,552 | 5,097,256 | **4,827,012** |
| `"s"` | 5,959,819 | 5,368,249 | 4,932,482 |
| `"z"` | 6,040,761 | 5,409,739 | 4,982,040 |

`3` wins at every stage, by 3% over `"z"` on the artefact that actually ships.
That is the opposite of the usual WebAssembly advice and the opposite of what
this crate's first draft asserted, which is the argument for measuring: the
bulk here is a rasterizer and three image codecs, whose inner loops `"z"`
declines to unroll and then pays for in call overhead and spill code. No
render-time tie-break was needed — `3` is both smallest and fastest.

**Budget: 5,792,414 bytes**, 20% above the measurement, enforced by
`scripts/wasm-package.nu`. The module lands **16.7% under** it. Twenty percent
leaves room for ordinary growth in the facade and still catches a step change:
a codec accidentally compiled in, a panic formatter, a `system-fonts` that
crept back.

`[profile.wasm]` is at the workspace root, not in the member — cargo ignores a
member's `[profile.*]` table and says nothing about it.

### Packaging, and why not `wasm-pack`

`nu scripts/wasm-package.nu` produces `crates/pdfrum-wasm/pkg` (git-ignored):
the module, the ES-module loader, `pdfrum.d.ts`, a `package.json` naming the
package `pdfrum`, and a README whose example renders a page into a canvas in
fifteen lines.

wasm-pack was the first choice and cannot drive this crate. It runs `wasm-opt`
itself with a hardcoded `-O` and no feature flags, and **that invocation fails
here**: rustc's `wasm32-unknown-unknown` emits bulk-memory (`memory.copy`,
`memory.fill`) and non-trapping float-to-int, and `wasm-opt`'s validator — which
still defaults to the 2017 MVP — rejects both unless told they are allowed. Nor
can the flags be supplied: wasm-pack reads
`[package.metadata.wasm-pack.profile.<name>]` only for `dev`, `release` and
`profiling`, and this crate builds under the workspace's own `wasm` profile,
under which it consults no metadata at all. Both `wasm-opt = false` and a full
flag list were tried under `.wasm` and `.release`; neither is read.

So the script calls the three tools directly. That also lets it record the size
before and after the optimizer and check the budget, which is where the numbers
above come from.

### Two things the gates found

**`js-sys` is not a `-sys` crate.** `scripts/ci.nu`'s pure-Rust check matches on
the name and flagged it. The `-sys` means the JavaScript *standard library*, not
a C one: nothing native to bind, and no `build.rs` in the published crate at
all. Exempted by name beside `linux-raw-sys`, with the reason.

**`cc` reaches the graph through the test harness.** `wasm-bindgen-test`
depends unconditionally on `minicov` (no feature turns it off in 0.3.78), which
build-depends on `cc`, which `deny.toml` bans outright and rightly. Measured
