# M15 — JavaScript via `boa` — status

Running record. The brief is `docs/design/pdfrum-script.md` (614ab62); the
rulings on its escalations are in PLAN.md §M15, SPEC.md §10 and STYLE.md §2b
(66e6014, and the E2 settlement below).

## E2 settled: the sandbox, measured against the oracle rather than read

The brief measured that boa's `RuntimeLimits` bound loops, recursion and
stack but not heap growth or regex backtracking. The user's ruling was to
document that *provided PDFium with V8 bounds none of it either*, and to
measure rather than assert. Our oracle build has `pdf_enable_v8=false`, so
the measurement used bblanchon/pdfium-binaries `chromium/8021`
(154.0.8021.0, 2026-08-25 — three days from our pinned `6f2272e`), driven by
a ~100-line C program over the public API that mirrors `pdfium_test`'s alert
hook. Driver, scripts and the full report: `docs/status/data/v8probe/`.

| case | PDFium + V8 | boa |
|---|---|---|
| `while(true){}` | never returns; SIGKILLed externally at 120 s and 600 s, 2 MB RSS | `RuntimeLimitError` in ~10 ms |
| heap growth (`Array(1000)` ×2M) | 860 MB cleanly at ×200k; at ×2M **1.58 GB then V8's `Reached heap limit` — SIGTRAP, core dump**, no PDFium callback | unbounded |
| `s=s+s` ×30 | stops at 17 MB on V8's intrinsic 2²⁹ `String::kMaxLength` as a RangeError PDFium **swallows silently** (no alert) | 1 GiB in 1.1 s |
| `/(a+)+$/` len 20/24/26/28/32/34 | 0.02 / 0.18 / 0.80 / 3.13 / 56.98 s / **killed at 120 s**; ~4× per +2 | same algorithm, same growth |

API audit of the shipped headers: no timeout, budget or terminate knob;
`FPDF_GetRecommendedV8Flags()` is `"--jitless"` alone; the only authored cap
is `kMaxAllowedBytes = 0x10000000` per `ArrayBuffer`, irrelevant to all three.
`ulimit -v` cannot even be used as an external control — V8's cage
reservation aborts at *initialisation* under it; a cgroup RSS cap is the
working external mechanism, for PDFium and for us alike.

**So the sentence PLAN §M15 wanted — "a stronger property than the C++ has"
— is true as written for loops, recursion and stack, and the two holes are
holes the oracle has too, one of them worse (a crash, not a hang).** Recorded
in SPEC §10 with the reopening condition.

## `AF*`: where we diverge from the oracle on purpose

The `AF*` library landed as `crates/pdfrum-script` (see the review at
`docs/reviews/claude-review-af-library.md` for the crate-versus-module
reconciliation). While reviewing it against `fxjs/cjs_publicmethods.cpp`,
`fxjs/cjs_util.cpp` and `fxjs/fx_date_helpers.cpp`, six behaviours turned out
to be **defects in the oracle rather than Acrobat's specification**. Each was
checked at its cited line, and against pdf.js — Mozilla's independent
implementation of the same Adobe-specified library — as an impartial second
reading.

**We implement the correct behaviour and diverge from the goldens where they
pin the defect.** Reproducing a one-character typo because a fixture records
its output would make the fixture, not the specification, our contract. Each
divergence is marked `// [oracle-bug]` in the source with both citations.

### The six

| # | What the oracle does | Where | What is correct | Second reading |
|---|---|---|---|---|
| 1 | 2000 is a common year and 1900 is a leap year | `fx_date_helpers.cpp:71` | The Gregorian rule: 2000 leap, 1900 common | pdf.js defers to JS `Date` |
| 2 | Every two-digit year becomes 2000–2099, so `85` is 2085 | `fx_date_helpers.cpp:330,556` | Pivot at fifty: `85` is 1985, `05` is 2005 | pdf.js `util.js:372-376` |
| 3 | Noon is `am`, and midnight prints as hour `0` | `cjs_publicmethods.cpp:517-535` | Noon is `pm`; both noon and midnight print as `12` | pdf.js `util.js:240-247` |
| 4 | `AFSimple('avg', …)` adds without dividing; `'min'` does not seed | `cjs_publicmethods.cpp:215-232` vs `:1341,1442,1456` | One name, one answer, whatever its case | pdf.js `aform.js:350-363` |
| 5 | `util.printd`'s `dddd`/`ddd` print `Sunday`/`Sun` for every date | `cjs_util.cpp:267` | The real weekday | pdf.js reads `oDate.getDay()` |
| 6 | `IsNumber("")` and `IsNumber("  ")` are `true` | `cjs_publicmethods.cpp:272-309` | Nothing is not a number | the oracle's own `TODO(weili)` |

Each in one line:

1. **Leap year.** `IsLeapYear` reads
   `(year % 4 == 0) && ((year % 100 != 0) || (year % 400 != 0))`. The last
   clause should be `year % 400 == 0`; as written it is true for every year not
   divisible by 400, so the century exception never fires and its own exception
   fires backwards. The only leap year `fx_date_helpers_unittest.cpp` checks is
   1972, which both spellings agree on. It also puts the test at odds with
   `DayFromYear` two functions above it, which counts leap days correctly.
2. **Two-digit years.** `int nYearSub = 99;  // nYear - 2000;` — the intended
   formula is in the comment and was never written; `:556` then maps `0..=99`
   to `2000..=2099` unconditionally. A birth date typed `31/12/85` lands in
   2085.
3. **The twelve-hour clock.** `nHour > 12 ? nHour - 12 : nHour` leaves midnight
   as `0`, and the matching `nHour > 12 ? 'p' : 'a'` labels noon `am`.
4. **`AVG` and the case of the name.** `ApplyNamedOperation` matches with
   `EqualsASCIINoCase`, but the average's divide and the extremum's seed test
   the name again with the case-*sensitive* `EqualsASCII`. So `'avg'` reaches
   the combining step, adds, and never divides — answering a sum under an
   average's name.
5. **The weekday.** `struct tm time = {}` is filled with year, month, day, hour,
   minute and second but never `tm_wday`, which `wcsftime`'s `%A`/`%a` read
   directly rather than deriving.
6. **The empty string.** The walk returns true on reaching the terminator. The
   oracle's own unit test carries
   `// TODO(weili): Check whether results from case 0, 1, 10, 15 are intended.`,
   naming these two among them.

### What M14's exit criteria could not have caught

The brief's E1 was right, and it is worth restating as the finding rather
than as a premise. M14 shipped `Cascade` and `NoScripts`, every one of its
tests passed, and **none of the seam's three wires existed**:

- `commit::run` was called by nothing but its own unit tests;
- `route::Context` had no cascade and `route::apply` no parameter for one;
- `Cascade::keystroke` had no call site anywhere in the crate.

No exit criterion could have caught this, because `NoScripts` *is* the
identity cascade: a cascade that changes nothing is indistinguishable from
one that never runs. The tests that would have caught it are the eight in
`crates/pdfrum-form/tests/cascade_wiring.rs`, and they assert the opposite
property from everything else in the suite — that a cascade which **does**
something changes what routing does. Each fails if the hook it names loses
its caller again.

### E1: a parameter, not a `Context` field

Ruled, and landed as ruled. `apply`, `choose` and `kill_focus` take
`cascade: &mut dyn Cascade` second; `close_popup`, `focus_of`, `popup_view`
and `scroll_view` commit nothing and are unchanged. Internally the parameter
reaches fifteen functions, computed as the transitive closure over the call
graph rather than guessed.

`choose` takes the parameter and does not yet spend it, and that is upstream's
shape rather than an omission: `CFFL_ComboBox::SaveData`
(`fpdfsdk/formfiller/cffl_combobox.cpp:90`) runs only from `CommitData`,
which only `KillFocusForAnnot` calls, so choosing a row changes the selection
and the scripts run when the field is left. The parameter is on the signature
because E1 names it one of the three entry points that *can* reach a commit,
and a caller must not have to discover later that it needs one.

**The board did not move.** `conformance run --check-regressions` reports no
regressions, and a field-by-field diff of all 1705 rows against the committed
board — status, tags, `tier_a`, `tier_b` — reports **0 changed, 0 vanished, 0
appeared**. That is the whole of what "byte-identical behaviour for every
existing caller" means, and it is measured rather than asserted.

### E6: `/CO`, and the rule that decides it

`Form::calculation_order(&self, catalog, r) -> Vec<usize>` in `pdfrum-doc`,
additive. The rule that matters is the negative one: **a document with no
`/CO` array runs no calculation at all**, however many of its fields carry
`/AA /C`. `CountFieldsInCalculationOrder` returns 0 and
`GetFieldInCalculationOrder` returns null the moment `GetArrayFor("CO")`
finds nothing (`core/fpdfdoc/cpdf_interactiveform.cpp:739-761`), and the
sweep walks exactly that list — so an empty answer is *the* answer, and a
reader tempted to fall back to "every field, in `/Fields` order" would
recalculate documents the oracle leaves alone, visibly, on any file with a
calculation script and no `/CO`.

### E4: the four `Limits` fields, and one correction

Landed as ruled. One thing the brief did not know: `SessionConfig` already
carried a `max_calculate_depth`, added during M14 and defaulting to **8**.
Upstream's `busy_` (`fpdfsdk/cpdfsdk_interactiveform.cpp:259-264`) is a flag,
not a counter — the outer sweep is authoritative and every nested call
returns immediately — so the oracle permits **no** nesting at all. The field
now reads `Limits::default().max_calculate_depth`, which is 1.

### A63 — a failing validate keeps focus `[oracle-bug]`

Assigned here because it sits in the path this step rewired. PDFium's
`CFFL_FormField::CommitData` returns `true` from both refusal paths
(`fpdfsdk/formfiller/cffl_formfield.cpp:525-531`), and that return value is
`KillFocusForAnnot`'s only guard (`:306`), so `pWnd->KillFocus()` (`:311`)
and `EscapeFiller()` (`:324`) run whether the value was accepted or refused.
A user who typed something a validation script rejected finds the caret gone
and their typing discarded, with no way to correct it — which defeats the
purpose of a validation hook.

ISO 32000-1 §12.7.5.3 gives Validate the job of rejecting the *value*, not of
ending the interaction, and pdf.js implements that rule with the comment to
prove it: on the not-valid branch it sends `focus: true, // Stay in the
field.` (`src/scripting_api/event.js:277`, verified at the line). Under
PLAN.md's oracle-bug rule pdfrum reverts the edit **and keeps the field**;
`CommitOutcome::keeps_focus` is that answer, and `commit.rs`'s module
documentation carries both citations. **Zero board cost**, because the branch
is unreachable without scripts — nothing can refuse.

The `commit.rs` module doc that described the old behaviour as "the quirk
that must not be tidied" is replaced rather than amended: it was a correct
description of the oracle and a wrong instruction about what to do with it.

### `Keystroke`'s indices become `i32`, and `applied()` stops clamping

Brief §2.3 A4, and the reason is sharper than "the type was too narrow".
`CalcMergedString` (`fxjs/cjs_publicmethods.cpp:127-137`) has two halves that
**do not agree with each other**:

- the prefix is `value.First(SelStart())`, and `First(n)` is `Substr(0, n)`,
  which returns the **empty** string whenever `n` exceeds the length
  (`core/fxcrt/string_view_template.h:226-249`). `SelStart()` is an `int`
  widened to `size_t`, so `event.selStart = -1` produces an enormous count
  and an empty prefix — the field's leading text vanishes.
- the suffix is guarded explicitly by `end >= 0 && end < length`, which for a
  suffix is the same answer a clamp would give.

The old `.min(len)` clamp was the reasonable behaviour and the wrong one; it
kept text the oracle drops, on an input any `/AA /K` script produces in one
assignment. A reversed selection is also not swapped: prefix and suffix are
read independently, so crossing them duplicates text.

### Where `ScriptCascade` lives, and the brief's premise that changed

The brief §2.4 recommended a feature-gated module in `pdfrum-form` rather than
a new crate, and argued it from the dependency graph — every input except
`boa_engine` was already in `pdfrum-form`'s tree, `AF*` included, because
§1.2 put `AF*` in `crates/pdfrum-form/src/af/`.

**`AF*` shipped as `crates/pdfrum-script`, a separate crate.** So the argument
was re-run against what exists:

| where `ScriptCascade` lives | edges it needs | verdict |
|---|---|---|
| `pdfrum-script` | `pdfrum-script → pdfrum-form` (for `Cascade`), and then `pdfrum-form → pdfrum-script` to construct one | **the back-edge §2.4 warned about**, or a facade that makes every consumer know both names |
| `pdfrum-form::script` | `pdfrum-form → pdfrum-script`, one forward edge, plus `boa_engine` | clean |

The recommendation survives its premise. The counter-argument §2.4 stated
fairly also survives: a cargo feature is the **weaker** isolation mechanism,
because feature unification means any workspace member can turn it on for the
whole build, where the GPU backend is isolated by being a crate nothing
depends on. That is exactly why `scripts/check-no-boa.sh` is not optional and
why it carries the fourth, converse assertion.

### The binding shape, which is what the follow-on copies

Stated once in `bind.rs`'s module documentation so a follow-on adding object
model does not have to invent it:

1. **A free `fn(&JsValue, &[JsValue], &mut Context) -> JsResult<JsValue>`**,
   registered with `NativeFunction::from_fn_ptr`. Not a closure — boa's
   closures must be `Copy`, which rules out capturing host state.
2. **The host state lives in boa's own `HostDefined` slot**, so a function
   pointer reaches the transcript through the `&mut Context` it already has.
   `Context::get_data` hands back `&T`, hence `Rc<RefCell<HostState>>`.
3. **A missing argument is `undefined`, not an error** — several fixtures
   assert the resulting message rather than a panic.

A stub is never a `todo!()` and never a panic. Most of the Tier-2 surface is
"returns success and does nothing" *upstream*, so reproducing that is correct
behaviour rather than a shortcut, and a script calling `app.browseForDoc`
must not bring the process down.

### The sandbox, tested rather than claimed

The E2 measurement above said what the bounds are; these are the tests that
hold us to them. All in `crates/pdfrum-form/src/script/tests.rs`, and the
whole file runs in **0.159 s**.

| property | how it is asserted |
|---|---|
| `while(true)` terminates | the hook **refuses** and a `ScriptLimitReached` diagnostic is recorded — 0.115 s, against PDFium+V8's external SIGKILL at 600 s |
| deep recursion terminates | same shape, `max_script_recursion = 64` |
| stack exhaustion terminates | same shape, `max_script_stack = 512` |
| every hook refuses rather than accepts | four hooks, four refusals, one test |
| `max_calculate_depth = 1` refuses nesting | the second, nested sweep writes nothing |
| no I/O is reachable | 27 names enumerated in-engine and asserted `undefined` |
| a hostile field value cannot escape its literal | six spellings, including ` ` and a quote-comment splice |

**The assertions are on the diagnostic and the refusal, never on elapsed
time.** A timing assertion would be flaky on a loaded machine — this project
has measured its own at load 42 — and it would also be the wrong claim: what
matters is not that the script was fast, it is that it *stopped* and that the
hook took its **refusing** answer. Taking the permissive one would be the
failure mode that lets a hostile file walk past a validator, so that is the
half the tests actually check.

The I/O test is an enumeration rather than a reading of the source, which is
the difference between a security claim and a security property.
`SharedArrayBuffer` is deliberately **not** on the list: boa provides it, it
reaches nothing outside the realm, and no fixture asks about it.
`WebAssembly` and `gc` are, because `v8_features_expected.txt` asserts
`typeof` each and boa provides neither — which is a golden that passes for
free.

### boa's admission, measured

Full audit in DEPS.md. The headline numbers: **116 crates added, zero
`-sys`, zero `cc`/`cmake`/`bindgen`, `cargo deny --all-features check` clean
with no `deny.toml` edit needed** (every `OR` licence expression resolves to
an allowlisted branch), zero boa crates in any workspace member's default
tree, MSRV 1.91.0.

`default-features = false` is load-bearing rather than tidiness: the three
defaults are `float16`, `xsum` and `temporal`, and `temporal` alone drags
`icu_calendar`, `temporal_rs` and `timezone_provider` — an ICU tree, in a
project whose dependency manifest boasts that `unicode-bidi` "replaces the
entire ICU dependency", for a `Temporal` API no PDF script has ever called.
The dates PDF scripts *do* use go through `util.printd`/`util.scand`, which
are pure functions in `pdfrum-script` and reach no engine at all.

**M13 inherits one fact**: the MSRV floor is per-*feature*, not per-workspace,
because the feature is default-off. It must be written down in M13's
declaration rather than discovered by a consumer.

### A fourth and fifth not-achievable-by-construction fixture, found by running

The brief §5.3 records `gc` and `WebAssembly` as "verified absent: `typeof gc`
and `typeof WebAssembly` are both `"undefined"` in boa, **which is what
`v8_features_expected.txt` asserts**. Free."

**It asserts the opposite for `gc`**, and the golden says so in two lines:

```
Alert: PASS: typeof gc = function
Alert: PASS: typeof WebAssembly = undefined
```

Tracing where `gc` comes from settles what to do about it. It is **not**
PDFium's: `FPDF_GetRecommendedV8Flags()` returns `"--jitless"` alone
(`fpdfsdk/fpdf_view.cpp:1313-1318`), and the only `--expose-gc` in the tree is
`testing/v8_initializer.cpp:89` — `"--predictable --expose-gc"`, a **test
harness** flag. A production PDFium embedding has no `gc` either. So the
assertion is about the fixture runner's own V8 configuration, not about PDF,
which is exactly the category E3 put `apply`, `array_buffer` and
`immutable_proto` in.

Two fixtures depend on it:

| fixture | what it needs | bucket |
|---|---|---|
| `v8_features` | `typeof gc === "function"` | V8-intrinsic |
| `foreground_task` | `gc({type:'major', execution:'async'})` returning a thenable, and its `.then` resolving after an `app.alert` | V8-intrinsic |

**We decline both rather than bind a fake `gc`.** A stub would make
`v8_features` pass by asserting something false about ourselves — the whole
point of that fixture is to report which engine intrinsics the runtime has —
and `foreground_task`'s is worse, because it wants a *specific asynchronous
scheduling order* out of a garbage collector we do not have and would be
faking. Under the same reasoning E3 used to decline V8's error strings —
"that would be asserting something about a language, not about PDF" — this is
asserting something about a debug build's flags.

**So the exit restates once more: 47/47 accounted for, 42 byte-exact, 5 not
achievable by construction** — `apply`, `array_buffer` and `immutable_proto`
(V8's own exception text) plus `v8_features` and `foreground_task` (V8's
`--expose-gc` intrinsic, which is the test harness's and not PDFium's). Five
declines, each with its citation, none of them a shortcut.
