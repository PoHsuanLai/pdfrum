## Delivered: conformance harness v1 + golden store

The `conformance` bin crate (tool ring: `anyhow`, `clap`, `png`, `sha2`,
`thiserror`) implements PLAN.md §5 as three subcommands. JSON and TOML are
hand-rolled over our own closed schemas for the same reason SSIM is (DEPS.md):
the scoreboard is the fitness function and the ratchet metric must never shift
under a dependency update. No DEPS.md change was needed.

### Modules

`json` (stable-order writer + parser) · `transcode` (oracle UTF-32LE → UTF-8) ·
`ssim` (grayscale SSIM, 8x8 box window, K1=0.01 K2=0.03, plus exact-match and
max-channel-diff) · `pixels` (PNG decode → RGBA) · `oracle` (`MD5:` line
parsing, pass definitions, determinism args) · `suppressions` ·
`corpus` (walk + filter) · `goldens` (content-keyed store + manifest) ·
`thresholds` (ratchet) · `pool` (std-thread worker pool, order-preserving) ·
`generate` · `run` · `triage`.

### Two oracle facts that shaped the design

- **`pdfium_test` writes artifacts next to its input**, ignoring cwd. The
  checkout is read-only, so every PDF (and every expanded `.in`) is copied into
  a per-file scratch dir as `input.pdf` before the oracle sees it; artifact
  names are therefore `input.pdf.<page>.png` store-wide. Verified after the
  full run: `git status --porcelain` in `pdfium-c++` is empty.
- **`--show-metadata` / `--show-pageinfo` / `--show-structure` are mutually
  exclusive** (the binary rejects any two) and print to **stdout**, while
  progress goes to stderr. A full golden set is therefore six invocations.
  Empty dump output is a valid golden — a PDF with no `/Info` produces no
  metadata at all, and Tier A must assert we print nothing too.

### Golden store (`conformance/goldens/`, gitignored)

Keyed by `sha256[..16]` of the PDF bytes, so the 46 `.in` templates whose
expansion equals a checked-in `.pdf` share one directory. Each holds a
`manifest.json` (sources, page count, artifact list, oracle md5 lines, oracle
failures) plus the artifacts. Resumable: a directory with a manifest is skipped
unless `--force`.

Full run (16 workers, ~7 s): **1468 corpus+resource entries** (251 skipped as
xfa/suppressed for our `linux/nov8/noxfa/agg` build) → **1357 distinct PDFs,
10,564 artifacts, 1712 rendered pages, 68 MB, 0 failures**. Recorded rather
than dropped: 32 files the oracle cannot load (encrypted/damaged — the
`FRC_3.5_*` and `bug_*` fixtures) and 3 files whose `--annot` pass exits
nonzero (`redact_annot`, `bug_1098213`).

### Scoreboard and the M0 baseline

`conformance/scoreboard.json` is committed (rows sorted by path, tags sorted,
fixed key order, SSIM to six decimals) — byte-identical across repeated runs
apart from the timestamp, so a real change is a small diff. `pdfrum-tool` is
still a stub, so the harness probes it once and tags every file
`unsupported-tool`: **1468 files, 0 pass, 1468 fail** — the intended "everything
failing is fine" M0 baseline. `run --check-regressions <old>` enforces the
monotone rule (verified: exits 1 when a previously-passing file fails).

### Tiering implemented

- **Tier A, byte-exact:** text (stored transcoded to UTF-8), annot / metadata /
  pageinfo / structure dumps, page count.
- **Tier B, perceptual:** per-page SSIM against the floor in
  `conformance/thresholds.toml` (global `0.99`, per-file overrides that may only
  *tighten* — a looser override is a hard parse error), plus exact flag and max
  channel diff; the worst page decides the file.
- Tier C (cross-backend) is deferred until two raster backends exist.

Tests: **141** (`cargo nextest run`), covering UTF-32LE transcode incl. the
oracle's exact byte layout, SSIM (identical = exactly 1.0, closed-form flat
pair, monotone in distortion, symmetry, sub-window images), md5-line parsing,
scoreboard JSON round-trip and the regression rule, threshold ratchet,
suppressions parsing, corpus filtering, worker-pool ordering. `cargo clippy
--workspace --all-targets -- -D warnings` and `bash scripts/ci.sh` green.

### CLI

```bash
conformance generate-goldens [--oracle P] [--checkout P] [--jobs N] [--force] [--dry-run]
conformance run [--tool P] [--jobs N] [--out P] [--check-regressions OLD]
conformance triage [--scoreboard P] [--json] [--top N]
```

Oracle path: `--oracle`, else `PDFRUM_ORACLE`, else
`../pdfium-c++/out/Release/pdfium_test` relative to the repo root. A missing
oracle fails with the `gn gen` / `ninja` commands to fix it.
